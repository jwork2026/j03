# 葫芦娃阵型作业

这是一个用 Java 编写的面向对象建模示例，在 j02 葫芦娃排序的世界观上扩展到二维战场。

运行 `make` 可以编译并运行当前示例：

```shell
make
```

当前实现：老爷爷指挥七个葫芦娃摆出长蛇阵，蛇精率领小妖摆出鹤翼阵，双方对峙后上演一小段交战。战场只允许生物走到相邻的空格子（禁止“瞬移”）。自带一个简化的游戏引擎（`GameEngine` + `Renderer`），在终端里逐帧播放摆阵过程。

## 作业要求

1. 仔细阅读代码，理解其继承层次与阵型抽象，指出其中不合理的设计之处并改正（提示：留意重复的代码与 `instanceof` 的使用）。

2. 新增至少两种阵型（如八卦阵、方阵、雁行阵等），要求**不修改**现有指挥与战场代码，仅通过新增 `Formation` 子类完成。

3. 两个阵营在同一战场上布阵时可能发生位置冲突。请设计冲突的检测与处理方式（如报告冲突、调整锚点或重新规划）；并支持“变阵”：已经就位的队伍从一种阵型变换到另一种阵型，变换过程中每个生物只允许移动到相邻（上下左右）的空格子，变阵过程要通过 `GameEngine` 逐帧展示。

## 思考题（不计分，写入 `REPORT.md` 可加分）

- 当前的交战是 `Main` 里硬编码的剧本。对照 j02 的 `SortKnowledge → SortPlan` 与本次的 `Formation → FormationPlan`，如果要让交战变成双方“战术”的对抗（如擒贼先擒王、各个击破、坚壁清野），战术该如何抽象？它与阵型有何本质不同（提示：对手会动，态势会变）？
- `Huluwa` 能否改为枚举？需要对现有继承层次付出什么设计代价？
