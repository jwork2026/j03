# 葫芦娃阵型作业

这是一个用 Java 编写的面向对象建模示例，在 j02 葫芦娃排序的世界观上扩展到二维战场。

运行 `make` 可以编译并运行当前示例：

```shell
make
```

当前实现：老爷爷指挥七个葫芦娃摆出长蛇阵，蛇精率领小妖摆出鹤翼阵，对峙后进入回合制交战——每回合双方战术各自读取战场，为本方每个成员重新决策动作（移动或攻击），全军行动；首领被击退的一方落败，胜负由双方战术的对抗涌现而来。战场只允许生物走到相邻的空格子（禁止“瞬移”）。自带一个简化的游戏引擎（`GameEngine` + `Renderer`），在终端里逐帧播放摆阵过程。

## 作业要求

1. 仔细阅读代码，理解其继承层次与阵型抽象，指出其中不合理的设计之处并改正（提示：留意重复的代码、`instanceof` 的使用，以及领域对象与游戏引擎之间的依赖方向——谁应该认识谁？）。

2. 新增至少两种阵型（如八卦阵、方阵、雁行阵等），要求**不修改**现有指挥与战场代码，仅通过新增 `Formation` 子类完成。

3. 两个阵营在同一战场上布阵时可能发生位置冲突。请设计冲突的检测与处理方式（如报告冲突、调整锚点或重新规划）；并支持“变阵”：已经就位的队伍从一种阵型变换到另一种阵型，变换过程中每个生物只允许移动到相邻（上下左右）的空格子，变阵过程要通过 `GameEngine` 逐帧展示。

4. 新增至少一种战术（如各个击破、围魏救赵、且战且退），要求不修改 `Battle` 的回合循环，仅通过新增 `Tactic` 实现类完成；让不同的战术组合对战，在 `REPORT.md` 中记录并分析结果。想一想：阵型可以一次性产出完整计划（`FormationPlan`），战术为什么必须逐回合重新决策？

5. 当前的战斗规则过于简单：战力一锤定音，弱者毫无还手之地——推演一下就会发现，在内置的两种战术下，妖精一方甚至**永远不可能获胜**。请重新设计生物能力与战斗规则，新规则下**双方都要有现实的获胜可能**，让对抗更有悬念、更好玩。方向自定，比如：
   - 把单一“战力”拆分成攻击、防御、敏捷等属性——攻击弱的生物可以更擅长躲避（被攻击时有机会闪开脱身），强者也许笨重迟缓；
   - 引入可控的随机性（注入固定种子的 `Random`，保证结果可复现）让命中与闪避不再是定数。

## 特别强调

- 本次作业最看重的是**仔细体验面向对象的设计过程**：每一处扩展都先想清楚“这个职责该给谁、抽象放在哪一层、对谁开放对谁隐藏”，再动手写代码；`REPORT.md` 中记录下你的设计权衡与推翻重来的过程，它与最终代码同样重要。
- 鼓励自由发挥，把它做成一个**可玩性更强的游戏**：玩法、规则、内容都不必局限于题目——比如换掉 ASCII 形式的渲染，基于 `Renderer` 接口自己写一个可视化渲染引擎（Swing 窗口、网页……），骨架已经为此留好了插口。

## 提交方式

- 全部代码（第 1 题的改正、第 2～5 题的实现，以及自由发挥的部分）保存在 `src` 目录下，可以覆盖原有代码；请保证 `make` 仍能编译并运行你的作品。
- 将第 1 题的分析与改正说明、第 2～5 题的面向对象设计思路与对战分析，以及自由发挥部分的玩法和运行说明，写入 `REPORT.md`。
- AI 会针对 `src` 下的代码和 `REPORT.md` 进行自动评审。
